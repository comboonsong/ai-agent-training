# Roadmap แดชบอร์ดคุณภาพน้ำแม่น้ำกก

อ้างอิง [PRD](../product/prd.md), [system design](../architecture/system-design.md) และ[แผนแบ่งงานทีม](../delivery/team-work-plan.md)

## Purpose & scope

เอกสารนี้จัดลำดับการสร้างฟีเจอร์ทั้ง 6 ข้อใน PRD เป็นช่วงงาน แบ่งเป็นรอบที่ทำพร้อมกันได้ และกำหนดว่าแต่ละช่วงงานแก้ส่วนประกอบใดของ system design

เอกสารนี้ไม่กำหนดรายชื่อบุคคล วันส่งมอบ งานย่อย หรือการทดสอบ งานย่อยกำหนดใน phase-design และ phase-plan ของแต่ละช่วง และไม่ครอบคลุมการนำระบบขึ้นให้ประชาชนใช้จริง ซึ่งยังรอ ADR 002

**วิธีแบ่งงาน:** parallel phases ความกว้างรอบละ 3 ช่วงงาน ตามคนที่ผู้ใช้ระบุ ได้แก่ Back-end, Front-end และ UX/UI design as code

เอกสารนี้บอกว่าช่วงงานใดทำพร้อมกันได้เท่านั้น ไม่ได้แจกงานให้ใครอัตโนมัติ การทำพร้อมกันจะลดเวลาได้จริงเมื่อทีมมีคนถือทุกช่วงงานในรอบ ในแต่ละรอบ ช่วงงานลำดับแรกเป็นของ Back-end ลำดับที่สองเป็นของ Front-end ลำดับที่สามเป็นของ UX/UI และช่วงสุดท้ายเป็นการรวมระบบ

ข้อแลกเปลี่ยนของวิธีนี้: ผู้ใช้เห็นผลงานเฉพาะเมื่อจบรอบ ผลงานชิ้นแรกที่เปิดดูได้คือ Phase 04 ระหว่างรอบ แต่ละช่วงงานพิสูจน์ได้เฉพาะที่รอยต่อของส่วนประกอบตัวเอง

ส่วนประกอบ "ระบบหน้าตา" ที่ช่วงงานของ UX/UI แก้ ยังไม่มีใน system design ต้องเพิ่มก่อน ดู Sequencing decisions และ Open questions

## Phases

### Wave 1 — 3 ช่วงงานขนาน

#### Phase 01 — งานประมวลผลข้อมูลตามรอบและชุดข้อมูลให้บริการ

อ่านตารางผิวน้ำและตะกอนดินจากฐานข้อมูล GCP แปลงเป็นผลตรวจรูปแบบเดียวกัน เลือกผลล่าสุดของแต่ละจุด ค่าตรวจวัด และประเภทตัวอย่าง แล้วเผยแพร่จุดตรวจกับผลล่าสุดเป็นชุดข้อมูลให้บริการตามรูปแบบที่ตกลงกับ Front-end พิสูจน์ได้ที่รอยต่อ: ผลที่เผยแพร่ตรงกับแถวในตารางต้นทาง และเมื่ออ่านต้นทางไม่ได้ ชุดเดิมยังอยู่ครบ

ช่วงนี้น่าจะเกินเพดานราว 5 งาน แต่แบ่งต่อในรอบเดียวกันไม่ได้เพราะมี Back-end คนเดียว การแยกออกจะต้องเพิ่มทั้งรอบ จึงคงไว้

- **Serves:** ผลตรวจล่าสุดรายจุด, แผนที่จุดตรวจและทิศทางการไหล
- **Touches:** งานประมวลผลข้อมูลตามรอบ, ชุดข้อมูลให้บริการ
- **Depends on:** none
- **Estimate:** 6–8 tasks

#### Phase 02 — เว็บแดชบอร์ด: แผนที่จุดตรวจและหน้ารายละเอียดจุด

แสดงแนวลำน้ำและจุดตรวจบนแผนที่ เลือกจุดแล้วเปิดหน้ารายละเอียดที่แยกผลผิวน้ำและตะกอนดิน พร้อมค่า หน่วย และวันเวลาที่ตรวจ ใช้ข้อมูลตัวอย่างตามรูปแบบที่ตกลงกับ Back-end พิสูจน์ได้ที่รอยต่อ: ข้อมูลตัวอย่างแต่ละกรณี รวมถึงไม่มีผลตรวจ และผลสองประเภทตรวจคนละวัน แสดงถูกต้องบนมือถือและคอมพิวเตอร์

- **Serves:** ผลตรวจล่าสุดรายจุด, แผนที่จุดตรวจและทิศทางการไหล
- **Touches:** เว็บแดชบอร์ด
- **Depends on:** none
- **Estimate:** 4–6 tasks

#### Phase 03 — ระบบหน้าตา: พื้นฐานและหน้ารายละเอียดจุด

UX/UI สร้างระบบหน้าตาเป็นโค้ด ได้แก่ สี ตัวอักษร ระยะห่าง คอมโพเนนต์ของหน้ารายละเอียดจุดและหมุดจุดตรวจ รวมถึงข้อความบนหน้าจอ พิสูจน์ได้ที่รอยต่อ: คอมโพเนนต์แสดงได้ครบทุกสถานะ ทั้งมีข้อมูล ไม่มีข้อมูล และผลคนละวัน บนหน้าจอขนาดมือถือและคอมพิวเตอร์

- **Serves:** ผลตรวจล่าสุดรายจุด, แผนที่จุดตรวจและทิศทางการไหล
- **Touches:** ระบบหน้าตา
- **Depends on:** none
- **Estimate:** 3–5 tasks

#### Phase 04 — ประชาชนเลือกจุดบนแผนที่ แล้วเห็นผลตรวจล่าสุดของผิวน้ำและตะกอนดิน พร้อมวันเวลาที่ตรวจ

รวมระบบของ Wave 1 เว็บอ่านชุดข้อมูลให้บริการจริงแทนข้อมูลตัวอย่าง และใช้คอมโพเนนต์จากระบบหน้าตา ประชาชนเปิดแผนที่ เลือกจุดตรวจ และอ่านผลล่าสุดที่ตรงกับข้อมูลต้นทาง

- **Serves:** ผลตรวจล่าสุดรายจุด, แผนที่จุดตรวจและทิศทางการไหล
- **Touches:** งานประมวลผลข้อมูลตามรอบ, ชุดข้อมูลให้บริการ, เว็บแดชบอร์ด, ระบบหน้าตา
- **Depends on:** Phase 01, Phase 02, Phase 03
- **Estimate:** 3–4 tasks

### Wave 2 — 3 ช่วงงานขนาน

#### Phase 05 — ตัวประเมินมาตรฐานและการเปลี่ยนแปลง พร้อมผลย้อนหลัง

จับคู่ผลตรวจกับเกณฑ์มาตรฐานจากไฟล์ JSON ให้สถานะเทียบมาตรฐาน คำนวณเปอร์เซ็นต์เทียบผลครั้งก่อน และเผยแพร่ผลย้อนหลัง 7 วันในชุดข้อมูลให้บริการ พิสูจน์ได้ที่รอยต่อ: ค่าที่ยังไม่มีเกณฑ์ และค่าที่คำนวณเปอร์เซ็นต์ไม่ได้ ถูกระบุสถานะชัดเจนโดยไม่เดาค่า

ช่วงนี้น่าจะเกินเพดานราว 5 งาน ด้วยเหตุผลเดียวกับ Phase 01 จึงคงไว้

- **Serves:** ผลตรวจล่าสุดรายจุด, กราฟแนวโน้มรายจุด
- **Touches:** ตัวประเมินมาตรฐานและการเปลี่ยนแปลง, ชุดข้อมูลให้บริการ
- **Depends on:** Phase 04
- **Estimate:** 6–8 tasks

#### Phase 06 — เว็บแดชบอร์ด: สถานะสี เปอร์เซ็นต์การเปลี่ยนแปลง และกราฟ 7 วัน

แสดงสถานะเทียบมาตรฐานเป็นสี เปอร์เซ็นต์เทียบครั้งก่อน และกราฟย้อนหลัง 7 วันที่เลือกจุด ค่าตรวจวัด และประเภทตัวอย่างได้ ใช้ข้อมูลตัวอย่างตามรูปแบบที่ตกลงไว้ พิสูจน์ได้ที่รอยต่อ: กราฟแสดงได้เมื่อไม่มีข้อมูลในช่วง และเมื่อมีจุดข้อมูลน้อย

- **Serves:** ผลตรวจล่าสุดรายจุด, กราฟแนวโน้มรายจุด
- **Touches:** เว็บแดชบอร์ด
- **Depends on:** Phase 04
- **Estimate:** 4–6 tasks

#### Phase 07 — ระบบหน้าตา: สีสถานะและรูปแบบกราฟ

กำหนดชุดสีสถานะเทียบมาตรฐานและความหมายของแต่ละสี รวมถึงสถานะที่ยังไม่มีเกณฑ์ และรูปแบบกราฟที่อ่านง่ายบนมือถือ พิสูจน์ได้ที่รอยต่อ: ทุกสถานะแยกออกจากกันได้โดยไม่พึ่งสีอย่างเดียว

- **Serves:** ผลตรวจล่าสุดรายจุด, กราฟแนวโน้มรายจุด
- **Touches:** ระบบหน้าตา
- **Depends on:** Phase 04
- **Estimate:** 3–4 tasks

#### Phase 08 — ประชาชนเห็นว่าค่าใดเกินมาตรฐาน เปลี่ยนไปกี่เปอร์เซ็นต์ และดูกราฟย้อนหลัง 7 วันได้

รวมระบบของ Wave 2 หน้ารายละเอียดจุดแสดงสถานะสีและเปอร์เซ็นต์จากผลประเมินจริง และกราฟย้อนหลังอ่านจากชุดข้อมูลให้บริการ

- **Serves:** ผลตรวจล่าสุดรายจุด, กราฟแนวโน้มรายจุด
- **Touches:** ตัวประเมินมาตรฐานและการเปลี่ยนแปลง, ชุดข้อมูลให้บริการ, เว็บแดชบอร์ด, ระบบหน้าตา
- **Depends on:** Phase 05, Phase 06, Phase 07
- **Estimate:** 3–4 tasks

### Wave 3 — 3 ช่วงงานขนาน

#### Phase 09 — โครงข่ายลำน้ำ

แปลง shapefile เป็นแนวลำน้ำพร้อมทิศทาง ผูกจุดตรวจกับลำน้ำ และสร้างตารางลำดับต้นน้ำ–ท้ายน้ำ ตามทิศทางที่ผู้ใช้ระบุหลังตรวจข้อมูลร่วมกัน แล้วเผยแพร่ในชุดข้อมูลให้บริการ พิสูจน์ได้ที่รอยต่อ: ทุกจุดตรวจผูกกับลำน้ำได้ และรายการจุดท้ายน้ำของแต่ละจุดตรงกับตารางที่คนตรวจแล้ว

- **Serves:** แผนที่จุดตรวจและทิศทางการไหล, คำแนะนำการปฏิบัติตัว
- **Touches:** โครงข่ายลำน้ำ, ชุดข้อมูลให้บริการ
- **Depends on:** Phase 08
- **Estimate:** 4–5 tasks

#### Phase 10 — เว็บแดชบอร์ด: ภาพเคลื่อนไหวทิศทางการไหล และคำแนะนำในหน้ารายละเอียดจุด

แสดงภาพเคลื่อนไหวทิศทางการไหลบนแนวลำน้ำ และแสดงคำแนะนำการปฏิบัติตัวในหน้ารายละเอียดจุดเมื่อค่าที่จุดนั้นเกินมาตรฐาน ใช้ข้อมูลตัวอย่างตามรูปแบบที่ตกลงไว้ พิสูจน์ได้ที่รอยต่อ: ภาพเคลื่อนไหวไม่ทำให้หน้าแผนที่ช้าเกินเป้าหมาย 5 วินาทีบนมือถือ

- **Serves:** แผนที่จุดตรวจและทิศทางการไหล, คำแนะนำการปฏิบัติตัว
- **Touches:** เว็บแดชบอร์ด
- **Depends on:** Phase 08
- **Estimate:** 4–5 tasks

#### Phase 11 — คลังเนื้อหา: คำแนะนำการปฏิบัติตัว

UX/UI จัดคำแนะนำการปฏิบัติตัวเป็นไฟล์ JSON แยกตามค่าตรวจวัดและประเภทตัวอย่าง จากเอกสารที่ผู้ใช้ส่งให้ และสร้างคอมโพเนนต์แสดงคำแนะนำในระบบหน้าตา เริ่มรอบนี้เพื่อให้มีเวลาตรวจรับเนื้อหา พิสูจน์ได้ที่รอยต่อ: ทุกค่าตรวจวัดที่มีเกณฑ์มีคำแนะนำ หรือถูกระบุว่ายังไม่มี

- **Serves:** แผนที่จุดตรวจและทิศทางการไหล, คำแนะนำการปฏิบัติตัว
- **Touches:** คลังเนื้อหา, ระบบหน้าตา
- **Depends on:** Phase 08
- **Estimate:** 3–5 tasks

#### Phase 12 — ประชาชนเห็นทิศทางการไหลบนแผนที่ และอ่านคำแนะนำเมื่อค่าที่จุดนั้นเกินมาตรฐาน

รวมระบบของ Wave 3 แผนที่แสดงทิศทางการไหลจากโครงข่ายลำน้ำจริง และหน้ารายละเอียดจุดแสดงคำแนะนำที่ผ่านการตรวจรับแล้ว สำหรับค่าที่เกินมาตรฐาน

- **Serves:** แผนที่จุดตรวจและทิศทางการไหล, คำแนะนำการปฏิบัติตัว
- **Touches:** โครงข่ายลำน้ำ, ชุดข้อมูลให้บริการ, คลังเนื้อหา, เว็บแดชบอร์ด, ระบบหน้าตา
- **Depends on:** Phase 09, Phase 10, Phase 11
- **Estimate:** 2–3 tasks

### Wave 4 — 3 ช่วงงานขนาน

#### Phase 13 — ตัวสร้างการแจ้งเตือน

หาผลตรวจใหม่ที่ยังเกินมาตรฐานในแต่ละรอบ แล้วสร้างการแจ้งเตือนที่แยกจุดที่ตรวจพบจริงออกจากจุดท้ายน้ำที่อาจได้รับผลกระทบ และเผยแพร่ในชุดข้อมูลให้บริการ พิสูจน์ได้ที่รอยต่อ: รันรอบเดิมซ้ำไม่สร้างการแจ้งเตือนซ้ำ และผลที่ไม่เกินมาตรฐานไม่ถูกแจ้ง

- **Serves:** แจ้งเตือนผลเกินมาตรฐานและจุดท้ายน้ำ, คำอธิบายค่าตรวจวัดและข้อจำกัดในการตีความ, คำแนะนำการปฏิบัติตัว
- **Touches:** ตัวสร้างการแจ้งเตือน, ชุดข้อมูลให้บริการ
- **Depends on:** Phase 12
- **Estimate:** 4–6 tasks

#### Phase 14 — เว็บแดชบอร์ด: ข้อความแจ้งเตือน และคำอธิบายค่าตรวจวัด

แสดงข้อความแจ้งเตือนที่แยกจุดตรวจพบจริงกับจุดท้ายน้ำ เปิดคำแนะนำจากข้อความแจ้งเตือนได้ และแสดงคำอธิบายข้างชื่อค่าตรวจวัด ใช้ข้อมูลตัวอย่างตามรูปแบบที่ตกลงไว้ พิสูจน์ได้ที่รอยต่อ: ไม่มีข้อความแจ้งเตือนเมื่อไม่มีการแจ้งเตือน

- **Serves:** แจ้งเตือนผลเกินมาตรฐานและจุดท้ายน้ำ, คำอธิบายค่าตรวจวัดและข้อจำกัดในการตีความ, คำแนะนำการปฏิบัติตัว
- **Touches:** เว็บแดชบอร์ด
- **Depends on:** Phase 12
- **Estimate:** 4–5 tasks

#### Phase 15 — คลังเนื้อหา: คำอธิบายค่าตรวจวัด และระบบหน้าตาของการแจ้งเตือน

UX/UI จัดคำอธิบายค่าตรวจวัดและข้อจำกัดในการตีความเป็นไฟล์ JSON และสร้างคอมโพเนนต์ของข้อความแจ้งเตือนและคำอธิบาย รวมถึงข้อความที่ต่างกันระหว่างจุดตรวจพบจริงกับจุดท้ายน้ำ พิสูจน์ได้ที่รอยต่อ: ทุกค่าตรวจวัดที่แสดงบนเว็บมีคำอธิบาย หรือถูกระบุว่ายังไม่มี

- **Serves:** แจ้งเตือนผลเกินมาตรฐานและจุดท้ายน้ำ, คำอธิบายค่าตรวจวัดและข้อจำกัดในการตีความ, คำแนะนำการปฏิบัติตัว
- **Touches:** คลังเนื้อหา, ระบบหน้าตา
- **Depends on:** Phase 12
- **Estimate:** 3–5 tasks

#### Phase 16 — ประชาชนเห็นการแจ้งเตือนจุดที่เกินมาตรฐานและจุดท้ายน้ำ พร้อมคำแนะนำ และอ่านคำอธิบายค่าตรวจวัดได้

รวมระบบของ Wave 4 เมื่อมีผลตรวจใหม่ที่ยังเกินมาตรฐาน แดชบอร์ดแสดงการแจ้งเตือนจากข้อมูลจริง พร้อมคำแนะนำที่เกี่ยวข้อง และประชาชนอ่านคำอธิบายของทุกค่าตรวจวัดที่แสดงได้

- **Serves:** แจ้งเตือนผลเกินมาตรฐานและจุดท้ายน้ำ, คำอธิบายค่าตรวจวัดและข้อจำกัดในการตีความ, คำแนะนำการปฏิบัติตัว
- **Touches:** ตัวสร้างการแจ้งเตือน, ชุดข้อมูลให้บริการ, คลังเนื้อหา, เว็บแดชบอร์ด, ระบบหน้าตา
- **Depends on:** Phase 13, Phase 14, Phase 15
- **Estimate:** 3–4 tasks

## Sequencing decisions

1. **แยก "ระบบหน้าตา" ออกจากเว็บแดชบอร์ด ให้ UX/UI เป็นเจ้าของ** — ผู้ใช้ยอมรับ ทำให้ Front-end และ UX/UI ทำในรอบเดียวกันโดยไม่แก้ไฟล์ชุดเดียวกัน ทางที่ไม่เลือก: ให้ UX/UI ทำงานออกแบบในรอบก่อน Front-end ซึ่งไม่ชนกัน แต่ Front-end ต้องรอทุกรอบ และการทำขนานจะเหลือแค่สองคน การตัดสินใจนี้ต้องรัน system-design อีกรอบเพื่อเพิ่มส่วนประกอบ
2. **เตรียมคำแนะนำการปฏิบัติตัวใน Wave 3 และคำอธิบายค่าตรวจวัดใน Wave 4** — ผู้ใช้ยอมรับ คำแนะนำเป็น must-have และต้องมีแหล่งอ้างอิงกับผู้ตรวจรับ การเริ่มเร็วหนึ่งรอบให้เวลาตรวจรับ ทางที่ไม่เลือก: ทำคำอธิบายก่อน ซึ่งให้ประชาชนเห็นคำอธิบายเร็วขึ้นหนึ่งรอบ แต่คำแนะนำซึ่งสำคัญกว่าจะมีเวลาตรวจรับรอบเดียว
3. **เทียบมาตรฐานและแนวโน้ม (Wave 2) ก่อนลำน้ำ (Wave 3)** — ผมเลือกเองโดยไม่ได้ถาม สถานะเทียบมาตรฐานเป็นแกนของผลตรวจล่าสุดรายจุดซึ่งเป็น must-have และทิศทางการไหลยังรอผลตรวจข้อมูลร่วมกัน ทางที่ไม่เลือก: ลำน้ำก่อน ซึ่งให้ภาพเคลื่อนไหวเร็วขึ้น แต่ต้องรอทิศทางจากผู้ใช้ และเลื่อนการแสดงค่าที่เกินมาตรฐานออกไป
4. **การแจ้งเตือนอยู่รอบสุดท้าย** — ไม่ใช่ทางเลือก ตัวสร้างการแจ้งเตือนต้องใช้ผลประเมินจาก Wave 2 และโครงข่ายลำน้ำจาก Wave 3
