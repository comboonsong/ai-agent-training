# การออกแบบระบบแดชบอร์ดคุณภาพน้ำแม่น้ำกก

อ้างอิง [PRD](../product/prd.md) และข้อสรุปจากการสัมภาษณ์ออกแบบระบบ การตัดสินใจที่ยังไม่สรุปมีสถานะ proposed ในหัวข้อ Decisions และถูกรวบรวมไว้ใน Open questions

## Purpose & scope

ระบบอ่านผลตรวจคุณภาพน้ำแม่น้ำกกจากฐานข้อมูลบน GCP ประมวลผลล่วงหน้าตามรอบ แล้วเผยแพร่เป็นชุดข้อมูลที่เว็บแดชบอร์ดอ่านไปแสดงให้ประชาชน ประชาชนอ่านได้อย่างเดียวโดยไม่ต้องเข้าสู่ระบบ

เอกสารนี้ครอบคลุมส่วนประกอบของระบบ ความรับผิดชอบและขอบเขตของแต่ละส่วน ข้อมูลระดับเอนทิตี การเชื่อมต่อกับระบบภายนอก และการตัดสินใจที่ย้อนกลับได้ยาก

เอกสารนี้ไม่ครอบคลุม:

- ระบบสำหรับผู้ดูแลและการแก้ไขผลตรวจ ซึ่ง PRD ยังไม่ได้กำหนด
- การแจ้งเตือนนอกแดชบอร์ด เช่น อีเมลหรือข้อความ ซึ่ง PRD ไม่ได้ขอ
- รายการที่ PRD ปฏิเสธไว้ในหัวข้อ Deferred & rejected
- ชื่อฟิลด์ รูปแบบไฟล์ และรายการหน้าจอ ซึ่งกำหนดในการออกแบบรายช่วงงาน
- ลำดับการพัฒนาและช่วงส่งมอบ ซึ่งกำหนดใน roadmap

## Context & constraints

**ผลสำรวจสิ่งที่มีอยู่:** ตรวจที่เก็บโค้ดแล้วไม่พบโค้ด ไฟล์ dependency เอกสารออกแบบระบบ หรือ ADR เดิม จึงเป็นงานเริ่มใหม่ทั้งหมด มีเพียง URD, PRD และแผนแบ่งงานทีม

**ข้อจำกัดจาก PRD ที่กำหนดรูปร่างของระบบ:**

- ข้อมูลต้นทางอยู่ในฐานข้อมูลบน GCP แยกเป็นตารางผิวน้ำและตารางตะกอนดิน มีรหัสจุดตรวจร่วมกันและพิกัด เก็บตัวอย่างคนละตารางเวลา คพ. เป็นผู้ให้บริการข้อมูล
- ยังไม่มีใครตรวจบริการฐานข้อมูล โครงสร้างตาราง หน่วยวัด shapefile หรือเอกสารมาตรฐานจริง
- ประชาชนเปิดดูได้โดยไม่ต้องสมัครสมาชิกหรือเข้าสู่ระบบ และแก้ไขผลตรวจไม่ได้
- ใช้งานได้ทั้งมือถือและคอมพิวเตอร์
- ทีมมี UX/UI 1 คน และ Dev 2 คน ตาม[แผนแบ่งงานทีม](../delivery/team-work-plan.md)

**ข้อกำหนดที่ยืนยันแล้วในการสัมภาษณ์ออกแบบระบบ:**

- **ประสิทธิภาพ:** หน้าแดชบอร์ดแสดงแผนที่และผลตรวจเริ่มต้นพร้อมใช้งานภายใน 5 วินาที อย่างน้อย 95% ของการเปิดหน้า
- **ความพร้อมให้บริการ:** เปิดใช้ได้ตลอด 24 ชั่วโมง พร้อมให้บริการอย่างน้อย 99% ต่อเดือน

PRD ยังมีเครื่องหมาย Proposed ที่สองข้อนี้ ต้องแก้ PRD ให้ตรงกัน เงื่อนไขทดสอบของเป้าหมายประสิทธิภาพ (จำนวนผู้ใช้พร้อมกัน อุปกรณ์ เครือข่าย) ยังต้องกำหนด

**ข้อสรุปเรื่องสภาพแวดล้อม:** ช่วงนี้พัฒนาและสาธิตบนเครื่องของทีม โดยอ่านข้อมูลจาก GCP ที่วางระบบจริงสำหรับประชาชนยังไม่ตัดสิน ดู ADR 002 เป้าหมายความพร้อมให้บริการ 99% มีผลเมื่อเลือกที่วางระบบจริง

**ผลต่อแผนแบ่งงานทีม:** แผนงานระบุว่า Dev 2 พัฒนา API ตาม ADR 001 ระบบไม่มีเซิร์ฟเวอร์ API งานของ Dev 2 คืองานประมวลผลและชุดข้อมูลให้บริการ ข้อตกลงรูปแบบข้อมูลระหว่าง Dev 1 กับ Dev 2 ยังจำเป็นเหมือนเดิม

## Components

### เว็บแดชบอร์ด

หน้าจอที่ประชาชนใช้บนมือถือและคอมพิวเตอร์ แสดงแผนที่ลำน้ำและจุดตรวจ ภาพเคลื่อนไหวทิศทางการไหล รายละเอียดผลตรวจรายจุด กราฟย้อนหลัง การแจ้งเตือน คำอธิบายค่าตรวจวัด และคำแนะนำการปฏิบัติตัว ไม่มีการเข้าสู่ระบบ ไม่เขียนข้อมูลกลับ และไม่คำนวณสถานะเทียบมาตรฐานเอง

- **Serves:** ผลตรวจล่าสุดรายจุด, แผนที่จุดตรวจและทิศทางการไหล, แจ้งเตือนผลเกินมาตรฐานและจุดท้ายน้ำ, กราฟแนวโน้มรายจุด, คำอธิบายค่าตรวจวัดและข้อจำกัดในการตีความ, คำแนะนำการปฏิบัติตัว
- **Depends on:** ชุดข้อมูลให้บริการ
- **Interface:** ทำงานในเบราว์เซอร์ อ่านไฟล์ของชุดข้อมูลให้บริการผ่าน HTTP แบบอ่านอย่างเดียว

### งานประมวลผลข้อมูลตามรอบ

อ่านตารางผิวน้ำและตารางตะกอนดินจากฐานข้อมูล GCP ตามกำหนดเวลา แล้วแปลงเป็นผลตรวจรูปแบบเดียวกันที่ระบุจุดตรวจ ประเภทตัวอย่าง ค่าตรวจวัด ค่า หน่วย และวันเวลาที่ตรวจ กำหนดว่าผลใดเป็นผลล่าสุดและผลใดเป็นครั้งก่อนหน้าของแต่ละจุด ค่าตรวจวัด และประเภทตัวอย่าง อ่านฐานข้อมูลต้นทางอย่างเดียว ไม่แก้ไขข้อมูลต้นทาง

- **Serves:** ผลตรวจล่าสุดรายจุด, กราฟแนวโน้มรายจุด
- **Depends on:** none
- **Interface:** ส่งชุดผลตรวจรูปแบบเดียวกันของแต่ละรอบให้ส่วนประกอบถัดไปภายในงานเดียวกัน

### ตัวประเมินมาตรฐานและการเปลี่ยนแปลง

จับคู่ผลตรวจแต่ละค่ากับเกณฑ์มาตรฐานตามค่าตรวจวัด ประเภทตัวอย่าง และหน่วย เพื่อให้สถานะเทียบมาตรฐานที่เว็บแสดงเป็นสี และคำนวณเปอร์เซ็นต์การเปลี่ยนแปลงเทียบผลครั้งก่อนหน้า ถือตารางเกณฑ์มาตรฐานซึ่งเก็บเป็นไฟล์ JSON ตาม ADR 004 ผลที่ยังจับคู่เกณฑ์ไม่ได้ หรือคำนวณเปอร์เซ็นต์ไม่ได้ ต้องถูกระบุสถานะนั้นอย่างชัดเจน ไม่เดาค่า

- **Serves:** ผลตรวจล่าสุดรายจุด, แจ้งเตือนผลเกินมาตรฐานและจุดท้ายน้ำ
- **Depends on:** งานประมวลผลข้อมูลตามรอบ
- **Interface:** รับผลตรวจรูปแบบเดียวกัน คืนผลประเมินต่อผลตรวจแต่ละค่า ประกอบด้วยสถานะเทียบมาตรฐานและการเปลี่ยนแปลงเทียบครั้งก่อน

### โครงข่ายลำน้ำ

ถือแนวลำน้ำสำหรับแผนที่ ทิศทางการไหล การผูกจุดตรวจกับลำน้ำ และลำดับต้นน้ำ–ท้ายน้ำของจุดตรวจ ข้อมูลตั้งต้นมาจาก shapefile ลำน้ำที่โครงการมี วิธีได้มาซึ่งทิศทางและลำดับยังเป็นข้อเสนอตาม ADR 003 โดยผู้ใช้จะระบุทิศทางหลังทีมตรวจข้อมูลร่วมกัน

- **Serves:** แผนที่จุดตรวจและทิศทางการไหล, แจ้งเตือนผลเกินมาตรฐานและจุดท้ายน้ำ
- **Depends on:** none
- **Interface:** ให้แนวลำน้ำพร้อมทิศทางสำหรับแสดงบนแผนที่ และให้รายการจุดท้ายน้ำของจุดตรวจที่ระบุ

### ตัวสร้างการแจ้งเตือน

หาผลตรวจใหม่ที่ยังเกินมาตรฐานในแต่ละรอบ แล้วสร้างการแจ้งเตือนที่ระบุจุดที่ตรวจพบค่าเกินมาตรฐาน และจุดท้ายน้ำที่อาจได้รับผลกระทบ โดยแยกสองกลุ่มนี้ออกจากกันเสมอ การแจ้งเตือนแสดงบนแดชบอร์ดเท่านั้น จำว่าผลตรวจใดประมวลผลไปแล้วเพื่อแยกผลใหม่ออกจากผลเดิม

- **Serves:** แจ้งเตือนผลเกินมาตรฐานและจุดท้ายน้ำ, คำแนะนำการปฏิบัติตัว
- **Depends on:** ตัวประเมินมาตรฐานและการเปลี่ยนแปลง, โครงข่ายลำน้ำ
- **Interface:** รับผลประเมินของรอบปัจจุบัน คืนรายการแจ้งเตือนที่อ้างถึงจุดตรวจ ค่าตรวจวัด และประเภทตัวอย่าง

### คลังเนื้อหา

ถือคำอธิบายค่าตรวจวัด ข้อจำกัดในการตีความ และคำแนะนำการปฏิบัติตัว แยกตามค่าตรวจวัดและประเภทตัวอย่าง รวมถึงข้อความที่ต่างกันระหว่างจุดที่ตรวจพบจริงกับจุดท้ายน้ำ เก็บเป็นไฟล์ JSON ในที่เก็บโค้ดตาม ADR 004 โดยผู้ใช้เป็นผู้ส่งเอกสาร JSON ให้ ไม่มีหน้าจอแก้ไขเนื้อหา

- **Serves:** คำอธิบายค่าตรวจวัดและข้อจำกัดในการตีความ, คำแนะนำการปฏิบัติตัว
- **Depends on:** none
- **Interface:** ให้เนื้อหาที่ค้นได้ด้วยค่าตรวจวัดและประเภทตัวอย่าง

### ชุดข้อมูลให้บริการ

ข้อมูลที่ประมวลผลแล้วของรอบล่าสุด ซึ่งเผยแพร่เป็นไฟล์ให้เว็บอ่าน ประกอบด้วยจุดตรวจ ผลล่าสุดพร้อมผลประเมิน ผลย้อนหลัง การแจ้งเตือน แนวลำน้ำ และเนื้อหา เป็นข้อตกลงรูปแบบข้อมูลระหว่าง Frontend กับ Data/Backend เผยแพร่ครั้งละทั้งชุด หากรอบประมวลผลล้มเหลว ชุดเดิมยังให้บริการต่อ

- **Serves:** ผลตรวจล่าสุดรายจุด, แผนที่จุดตรวจและทิศทางการไหล, แจ้งเตือนผลเกินมาตรฐานและจุดท้ายน้ำ, กราฟแนวโน้มรายจุด, คำอธิบายค่าตรวจวัดและข้อจำกัดในการตีความ, คำแนะนำการปฏิบัติตัว
- **Depends on:** งานประมวลผลข้อมูลตามรอบ, ตัวประเมินมาตรฐานและการเปลี่ยนแปลง, ตัวสร้างการแจ้งเตือน, โครงข่ายลำน้ำ, คลังเนื้อหา
- **Interface:** ไฟล์ข้อมูลแบบอ่านอย่างเดียวผ่าน HTTP ใช้โดยเว็บแดชบอร์ดเท่านั้น

## Data model

- **จุดตรวจ** — ตำแหน่งที่เก็บตัวอย่าง มีรหัสที่ใช้ร่วมกันระหว่างสองตารางต้นทาง ชื่อ และพิกัด
- **ประเภทตัวอย่าง** — ผิวน้ำหรือตะกอนดิน
- **ค่าตรวจวัด** — สารหรือค่าคุณภาพน้ำที่ถูกตรวจ
- **ผลตรวจ** — ค่าหนึ่งค่าของค่าตรวจวัดหนึ่งตัว ณ จุดตรวจหนึ่งจุด ของประเภทตัวอย่างหนึ่งประเภท พร้อมหน่วยและวันเวลาที่ตรวจ
- **เกณฑ์มาตรฐาน** — เกณฑ์และหน่วยของค่าตรวจวัดหนึ่งตัวสำหรับประเภทตัวอย่างหนึ่งประเภท
- **ผลประเมิน** — สถานะเทียบมาตรฐานและการเปลี่ยนแปลงเทียบครั้งก่อนของผลตรวจหนึ่งค่า
- **ช่วงลำน้ำ** — เส้นลำน้ำหนึ่งช่วงพร้อมทิศทางการไหล
- **ความเชื่อมโยงต้นน้ำ–ท้ายน้ำ** — ความสัมพันธ์ว่าจุดตรวจใดอยู่ท้ายน้ำของจุดตรวจใด
- **การแจ้งเตือน** — บันทึกว่าผลตรวจใหม่ค่าใดยังเกินมาตรฐาน และจุดท้ายน้ำใดอาจได้รับผลกระทบ
- **คำอธิบายค่าตรวจวัด** — ความหมาย ความเกี่ยวข้องกับคุณภาพน้ำ และข้อจำกัดในการตีความของค่าตรวจวัดหนึ่งตัว
- **คำแนะนำการปฏิบัติตัว** — ข้อความแนะนำสำหรับค่าตรวจวัดและประเภทตัวอย่างหนึ่งคู่

ความสัมพันธ์: จุดตรวจมีผลตรวจหลายค่า ผลตรวจแต่ละค่าอ้างถึงค่าตรวจวัดและประเภทตัวอย่างอย่างละหนึ่ง และมีผลประเมินได้หนึ่งรายการ เกณฑ์มาตรฐาน คำอธิบาย และคำแนะนำผูกกับค่าตรวจวัด โดยเกณฑ์และคำแนะนำแยกตามประเภทตัวอย่างด้วย จุดตรวจผูกกับช่วงลำน้ำ และเชื่อมถึงจุดตรวจอื่นผ่านความเชื่อมโยงต้นน้ำ–ท้ายน้ำ การแจ้งเตือนอ้างถึงผลประเมินที่เป็นต้นเหตุและจุดตรวจท้ายน้ำที่เกี่ยวข้อง

## Integrations

- **ฐานข้อมูลผลตรวจบน GCP** — งานประมวลผลข้อมูลตามรอบเป็นฝ่ายเรียก อ่านอย่างเดียว โปรโตคอลยังระบุไม่ได้จนกว่าจะทราบบริการฐานข้อมูลจริง เมื่อใช้งานไม่ได้ รอบนั้นล้มเหลวโดยไม่เผยแพร่ชุดข้อมูลใหม่ แดชบอร์ดยังแสดงชุดล่าสุดที่เผยแพร่ไว้ พร้อมวันเวลาที่ตรวจของแต่ละผล
- **แผนที่ฐาน** — ยังไม่ได้ตัดสินว่าเว็บจะใช้แผนที่ฐานจากผู้ให้บริการภายนอกหรือไม่ ดู Open questions

เอกสารมาตรฐานของ คพ. shapefile ลำน้ำ และเอกสาร JSON ของเนื้อหา เป็นข้อมูลที่ทีมรับมาและจัดเก็บด้วยมือ ไม่ใช่การเรียกระบบภายนอกขณะทำงาน

## Open questions

**การตัดสินใจที่ยังเป็น proposed**

1. **ที่วางระบบจริงและภาษาของงานประมวลผล (ADR 002):** ช่วงนี้พัฒนาและสาธิตบนเครื่องของทีม ยังไม่ตัดสินว่าจะนำขึ้นให้ประชาชนใช้ที่ไหน และยังไม่ได้ยืนยันภาษา Python เป้าหมายความพร้อมให้บริการ 99% ต้องนำมาพิจารณาเมื่อตัดสิน
2. **ทิศทางการไหลและลำดับจุดตรวจ (ADR 003):** รอผู้ใช้ระบุทิศทางหลังทีมตรวจข้อมูลร่วมกัน

**สิ่งที่การออกแบบนี้ยังต้องรอ**

3. **บริการฐานข้อมูลจริงบน GCP:** กำหนดวิธีที่งานประมวลผลเชื่อมต่อ และสิทธิ์ที่ต้องขอ
4. **ความถี่ของรอบประมวลผล:** ต้องกำหนดจากความถี่ของผลตรวจจริงและระยะเวลาจากรับข้อมูลถึงแจ้งเตือนที่ยอมรับได้
5. **เอกสาร JSON ของเกณฑ์มาตรฐานและเนื้อหา:** รอผู้ใช้ส่งให้ ยังไม่ทราบโครงสร้างและความครอบคลุมของเอกสาร
6. **แผนที่ฐาน:** ต้องตัดสินว่าจะแสดงแผนที่ฐานใต้แนวลำน้ำหรือไม่ และใช้จากแหล่งใด ซึ่งมีผลต่อเป้าหมายประสิทธิภาพและการพึ่งพาผู้ให้บริการภายนอก
7. **เงื่อนไขทดสอบเป้าหมายประสิทธิภาพ:** ยืนยันตัวเลข 5 วินาทีที่ 95% แล้ว แต่ยังไม่ได้กำหนดจำนวนผู้ใช้พร้อมกัน อุปกรณ์ เครือข่าย และปริมาณข้อมูลที่ใช้ทดสอบ
8. **ระบบสำหรับผู้ดูแล:** PRD ยังไม่ได้กำหนด การออกแบบนี้จึงไม่มีส่วนประกอบสำหรับผู้ดูแล

**ประเด็นเปิดจาก PRD ที่ยังคงอยู่**

9. **สีและสถานะเทียบมาตรฐาน:** ชุดสี ความหมาย และกรณียังไม่มีเกณฑ์ที่จับคู่ได้
10. **การจับคู่ข้อมูลและเปอร์เซ็นต์ครั้งก่อน:** หน่วย นิยามผลล่าสุดและครั้งก่อน และการแสดงผลเมื่อไม่มีข้อมูลก่อนหน้า ค่าก่อนหน้าเป็นศูนย์ หรือผลไม่ใช่ตัวเลข
11. **ขอบเขตและพฤติกรรมการแจ้งเตือน:** ขอบเขตจุดท้ายน้ำเมื่อมีทางแยกหรือข้อมูลลำน้ำไม่ครบ นิยามข้อมูลใหม่ และกรณีผลถูกส่งซ้ำหรือแก้ไขภายหลัง
12. **ขอบเขตช่วงเวลาและข้อมูลแนวโน้ม:** ขอบเขตเวลาและเขตเวลาของช่วง 7 วัน ความถี่ข้อมูลจริง และกรณีมีจุดข้อมูลน้อย
13. **เนื้อหาคำอธิบาย:** แหล่งอ้างอิงและผู้ตรวจรับ
14. **เนื้อหาคำแนะนำ:** ข้อความตามสารและประเภทตัวอย่าง แหล่งอ้างอิง ผู้ตรวจรับ และความแตกต่างระหว่างจุดตรวจพบจริงกับจุดท้ายน้ำ
15. **โครงสร้าง หน่วย มาตรฐาน และข้อมูลย้อนหลังจริง:** ตรวจสอบเมื่อเข้าถึงฐานข้อมูลและเอกสารต้นทาง

**สิ่งที่ต้องแก้ในเอกสารอื่น**

16. **PRD:** เอาเครื่องหมาย Proposed ออกจากข้อกำหนดประสิทธิภาพและความพร้อมให้บริการ และปิดประเด็นเปิดข้อ 9 และ 10 ของ PRD เพราะยืนยันแล้ว
17. **แผนแบ่งงานทีม:** ปรับงานของ Dev 2 จากการพัฒนา API เป็นงานประมวลผลและชุดข้อมูลให้บริการ ตาม ADR 001

ไม่มีฟีเจอร์ใดใน PRD ที่ไม่มีส่วนประกอบรองรับ และไม่มีฟีเจอร์ใดพึ่งพาฟีเจอร์ที่ถูกเลื่อน
